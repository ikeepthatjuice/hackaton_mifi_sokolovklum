## Новый отдельный APK: сначала пункты 1–3

Package `com.neurostenographer.llmspike.q4`, label «LLM Q4 RAW diagnostic». Устанавливается рядом с прежним spike. Только фиксированная вымышленная строка, ввода реального текста нет.

- Q4_K_M:396704928 bytes; SHA256 `2883b98c1396be553c252b27382cae54baad12b4087e6bec86af024bd412afa9`. dependencies.json и models/manifest.json содержат эту запись. По повторному поручению команды manifest добавлен до merge #2: три проверенные ML-записи дословно взяты из #2 (84cd4721cdb6735c7841426bc89d147808e69e70), к ним дописана только Q4.
- Проверен tokenizer.chat_template в реально скачанном GGUF: ChatML, eos151645, enable_thinking=false добавляет пустой `<think>\n\n</think>\n\n`. Этот префикс сохранён; `/no_think` задан отдельно. Native sampler — настоящий greedy, остановка по llama_vocab_is_eog. Добавлен русский prompt с двумя другими примерами (не тестовая фраза телефона).
- Raw callback вызывается до think-cleanup и валидатора. В production callback по умолчанию отсутствует. В изолированном APK он пишет только фиксированную синтетику в `LLM_SPIKE_RAW` и показывает raw на экране. `LLM_SPIKE_GUARD` сообщает accepted/reason/changed; итоговый displayText отдельно.
- Полные think-блоки удаляются; незавершённая мысль не считается видимым ответом. Если после очистки слова нарушены, guard возвращает исходный текст.

```bash
adb install -r llm-q4-raw-diagnostic.apk
adb shell am start -n com.neurostenographer.llmspike.q4/engine.llm.spike.SpikeActivity
adb logcat -s LLM_SPIKE_RAW:I LLM_SPIKE_GUARD:I AndroidRuntime:E
adb shell dumpsys meminfo com.neurostenographer.llmspike.q4
```

Нажать «Запустить локальную LLM» при авиарежиме/Wi-Fi off. Зафиксировать SHA нового APK, raw, очищенный ответ, accepted/reason, final displayText, cold/warm и PSS. Полный cold замер включает копирование assets, UI generate time — только generate/checksum/load/decode.

## Подтверждённый командой Q4-прогон на A51

Результаты сообщил тестировщик в чате 7 ноября; агент телефон лично не запускал.
Проверялся диагностический APK source `1d68a73658051ab302b03581405e946f36128a94`,
SHA-256 `9aa2906ca79a30702b64d2265c0f8cef17cc12b2f62e0119dc2363adcc3c8da1` — совпадение подтверждено тестировщиком.
Это standalone диагностика пунктов 1–3, а не общий pipeline из последующих коммитов #23.

| Параметр | Результат тестировщика |
|---|---|
| Устройство | Galaxy A51, Android 13, arm64, RAM 3.5 ГБ |
| Сеть | Авиарежим включён, Wi-Fi выключен; у APK нет INTERNET |
| RAW и final | «Мы не переносим встречу. Нужно 12 папок.» |
| Guard, оба прогона | accepted=true, changed=true |
| Cold | 71 448 мс |
| Warm | 15 168 мс |
| Память | Пик PSS 693 МБ; RSS около 750 МБ |
| Стабильность | Крэшей нет, процесс жив |

На фиксированной синтетической фразе сохранены слова, отрицание «не» и число 12;
модель добавила регистр и пунктуацию. Это подтверждает локальный inference без сети
на данном устройстве, но не общую точность на русском корпусе.

Ранее сообщённый Q8: warm 6 с, PSS около 917 МБ, та же фраза без оформления.
Новый warm Q4 медленнее примерно в 2.53 раза, PSS ниже примерно на 24%.
Методика старого Q8/SHA APK полностью не зафиксированы, это ориентировочное сравнение.
Cold не разбит по checksum/load/decode — нельзя приписывать все 71.448 с генерации.

Для 60 с аудио бюджет генерации составляет 18 с: warm standalone 15.168 с
показывает высокий риск отката всего результата по дедлайну. Число обработанных реплик
по одному scalar-замеру предсказывать нельзя. В #23 уже реализован batching до 4 chunks,
но его ускорение и timeout на телефоне **ещё не измерены**. Следующий прогон — общий
оптимизированный pipeline #24+#23: отдельно copy/load, generation, batch size/calls,
PSS и warning. Затем сравнивать короткий prompt, лимит output tokens и число потоков
на одинаковом синтетическом наборе; ускорение заранее не заявляется.

В #24 на прочитанном SHA `682dca4f62f4e029389ea440c5e266bf85cc1e78` DI ещё создаёт
`Postprocessor(LlamaCppTextGenerator(...))` с lazy load. Back должен заменить load callback
на `LocalTranscriptPostprocessor.load(model, BuildConfig.LLM_SHA256)` либо вызвать
`generator.prepare()` до возврата обёртки. Иначе первый native open всё ещё попадёт в
`process`, хотя ensureModel/копирование в #23 уже находятся за пределами таймаута.

Продолжение: [KV-префикс и 12-row батчи](LLM_KV_PERFORMANCE.md). Старые показатели выше относятся к предыдущей ревизии; новая производительность на A51 ещё не измерена.
