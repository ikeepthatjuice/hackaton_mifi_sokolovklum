Galaxy A51, Android 13, arm64, около 3.5 ГБ RAM; авиарежим включён, Wi-Fi выключен. JFK, английский, около 11 с аудио: общий cold 27.3 с (отдельно ещё 5.4 с на копирование весов), warm 26.2 с; RTF ≈2.48/2.38 без копирования. ASR 16.5 с, диаризация 5.8 с. Обработка медленнее реального времени на этом коротком примере; нельзя переносить этот RTF на минутный русский диалог.

Ранее неоптимизированный native ASR обрабатывал 11 с около 319 с. Это историческая Debug/-O0 сборка, а не скорость оптимизированного RC. Замеры release через UI ещё не подтверждены. Подробности, статусы и источник — [TEST_RESULTS.md](TEST_RESULTS.md); методика — [PROTOCOL.md](PROTOCOL.md).

## Бюджет LLM и частичное оформление

В историческом main #23 процесс был атомарным: при таймауте все реплики возвращались как rawText. После merge #24 в main f48d417 реализовано частичное сохранение: порции по 4 реплики, готовые порции сохраняются, остаток остаётся rawText. Warning имеет вид «Пунктуация и регистр обработаны в N из M реплик: исчерпан лимит времени LLM. Остальные — исходный текст».

N здесь — количество реплик в завершённых порциях, **не** число исправленных или принятых валидатором строк: отдельная строка внутри готовой порции может остаться rawText после guard. Для оценки качества отдельно считать changed/accepted и M. При ошибке LLM в #24 весь результат снова rawText + warning ошибки; явная отмена остаётся Cancelled.

Бюджет #24 — **max(30% длительности аудио, время первой порции)**: первая порция дорабатывает даже после 30%; это не строгая верхняя граница времени. Копирование/EngineSpec.load вне часов генерации. На прочитанном f735cbf DI всё ещё создаёт lazy LlamaCppTextGenerator: checksum/native open в первом generate могут попасть в первую порцию. Для исключения загрузки нужен eager prepare/load; успешная интеграция этого пункта здесь не заявляется.

На A51 старый Q4 diagnostic: cold 71.448 с / warm 15.168 с на 7 слов, PSS 693 МБ. Новый KV/batching diagnostic на телефоне ещё не измерен; ≥50% оформленных реплик за 18 с на минуте русского аудио — **цель, не достигнутый результат**. [A51-отчёт](A51_LLM_CHECKPOINT.md), [KV и batching](LLM_KV_PERFORMANCE.md), [бюджет #23](LLM_Q4_BATCH_BUDGET.md) описывают разные ревизии; при расхождении привязывать поведение к SHA.

## Русский язык, речь и говорящие

- Основной язык — русский, английский поддерживается. Whisper **base multilingual** используется с language=ru; JFK с language=en не подтверждает русское качество. WER/CER на русском пока не измерены.
- Русский диалог 73.5 с до исправления UTF-8 завершился крэшем ASR. Фикс есть в #24 f735cbf; повтор после фикса ещё ожидается. Нельзя считать этот диалог успешным end-to-end тестом.
- В том неуспешном русском прогоне наблюдались decode 17–26 с и diarization 181–192 с. Это частичные стадийные замеры, не общий RTF. Перекрытия речи, шум, короткие реплики и похожие голоса могут ухудшать разделение говорящих; accuracy/DER/overlap-метрики не измерены. Модель не обещает разнести одновременно звучащие слова без ошибок.
- LLM оформляет уже распознанные слова, не исправляет ASR и не переводит. Guard откатывает изменения слов/имён/чисел/отрицаний. Синтетика проверяет сохранность текста, не WER всего конвейера: [русская LLM-валидация](LLM_RUSSIAN_VALIDATION.md), [QA-план](Q1_TEST_PLAN.md).
