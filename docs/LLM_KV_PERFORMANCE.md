# Q4: KV-префикс и батчи до 12 реплик

7 ноября 2026. Изменения в feat/llm-qa-q4-budget, PR #23. Цель команды:
не менее 50% реплик минутной русской записи получают валидное оформление
в пределах 18 секунд генерации. На A51 эта цель после правки **ещё не проверена**.

## Причина повторного prefill и флаги APK

Старый diagnostic source1d68a73 / APK SHA9aa2906c… уже Release/-O3, а не Debug/-O0.
Доказательство: /tmp/syubik-q4v2-arm64/build.ninja для transcript_llm и bundled ggml
содержит -O3 -DNDEBUG. strip-unneeded сохранённой ARM64-библиотеки даёт
SHA256 d2e2a3ecba9031eec920ce4cc27571a3c9403ccd7c7d56642321103bdb917ad4,
совпадающий с lib/arm64-v8a/libtranscript_llm.so внутри проверенного APK.
NDK Release flags приходят из Android toolchain, поэтому пустой cache-параметр
CMAKE_CXX_FLAGS_RELEASE сам по себе не означает отсутствие оптимизации.

До правки каждый NativeBridge.generate создавал и освобождал context и снова
обрабатывал system + 2 примера. Теперь runtime владеет model и одним context.
Фиксированный префикс обрабатывается один раз для текущего режима scalar/batch,
KV остаётся между вызовами одного runtime. Токены пользовательских строк и ответа
удаляются через llama_memory_seq_rm(seq0, prefix_length, -1) до и после каждого вызова.
Кэш не разделяется между runtime/записями; при close освобождаются context и модель.
При смене scalar/batch prompt context пересоздаётся. Первый вызов нового режима
оплачивает prefill; последующие подают только новые строки и assistant suffix.

Токенизация BPE на границе префикса проверяется по точному совпадению токенов полного
prompt и фиксированного префикса. Ошибка/отмена инвалидирует context целиком;
callback прерывания не остаётся с указателем на завершённый JNI-вызов. Сохранены greedy,
/no_think, think cleanup и EOG stop. При другом порядке prefill возможны небольшие
различия регистра/пунктуации из-за floating point; guard слов обязателен.

Параметры: n_threads=n_threads_batch=4 по умолчанию (affinity не задаётся — выбор ядер
остаётся Android scheduler), n_batch=512, n_ubatch=128, n_ctx=2048. Нет второго context,
снимков KV на диске и дополнительных экспортов ggml. Память context теперь удерживается
между вызовами, поэтому новый пик PSS и освобождение после pipeline измерить на A51.

## Батч и неизменные защитные правила

По умолчанию до 12 chunks / 600 символов, включая [id] и разделители. Длинная реплика
по-прежнему делится по пробелам; число строк и id контролируются, каждая проверяется
отдельно. Максимум output tokens не увеличен (512): исчерпание лимита — ошибка LLM,
а не публикация обрезанного ответа. Один runtime работает последовательно под Kotlin Mutex.

Приоритетные фиксы 11f54a0 не изменены: ensureModel/copy и EngineSpec.load до timeout;
только process ограничен 30% длительности. Любая ошибка LLM → ВСЕ rawText +
«Пунктуация не обработана: ошибка локальной LLM», явная отмена → Cancelled.
Whole-process timeout по атомарному контракту также откатывает весь результат;
частично готовые пакеты не публикуются. Цель 50% пока оценивается по завершённому
списку (не по скрытым частичным ответам), изменение этой политики требует отдельного решения.
Для #24 всё ещё обязателен eager load через LocalTranscriptPostprocessor.load/prepare.

## Предварительный Linux-прогон (не Android RTF)

Реальная Qwen Q4, pinned llama.cpp954de248, Release/-O3, threads4. Одинаковые 12 русских
синтетических реплик; модель предварительно загружена, checksum/load исключены.
Сначала старый .so, затем новый, один host. Частота/температура CPU не фиксировались;
это инженерный sanity check, не строгий аппаратный benchmark.

| Сценарий | Старый context на каждый вызов | Новый KV/context |
|---|---:|---:|
| Scalar первый вызов, мс | 941 | 989 |
| Scalar повторы, мс | 923 / 904 / 892 | 339 / 364 / 348 |
| 12 реплик батчами по 4, первый / warm, мс | 4358 / 4262 | 3091 / 2374 |
| 12 реплик одним батчем, первый / warm, мс | 2839 / 2768 | 2892 / 2100 |

Для 12-row пути 1 native call вместо 3; 10/12 итоговых строк изменили оформление,
финальный TranscriptValidator принят. Неизменённые/отклонённые ответы остаются rawText.
Ускорение warm scalar около 61%, весь 12-row warm путь против прежних 4-row батчей
около 51%. Не пересчитывать эти проценты в предполагаемые секунды A51.

Проверено: LLM/JNI37/37 с реальной моделью (включая изоляцию KV, смену режима,
отмену/reuse/close), pipeline24/24, Python28/28. ARM64 и Linux native compile PASS;
экспортированы только 3 JNI entry points. Проверены 12 строк/600 символов и split батча.
Android Kotlin/D8 compile, APK signaturesv2/v3, zipalign и модель SHA проверены.
Standalone Gradle assemble/lint и прогон нового APK на телефоне не выполнялись.
Общий Android CI проверяется отдельно на SHA PR.

## A51: повторяемый протокол

Новый llm-q4-kv-diagnostic.apk устанавливается обновлением diagnostic .q4, тот же ключ.
Пакет не имеет INTERNET, raw logs доступны только для фиксированной синтетики.
Первый экран: scalar кнопка, cold/warm 3 раза; затем кнопка «Батч 12 реплик / бюджет 18 с»
дважды подряд. При переходе scalar↔batch префикс меняется: первый вызов холодный по KV.
На экране отдельно prepareMs и generationMs; в logcat LLM_SPIKE_GUARD также changed/12,
valid и timeout. Порог цели — changed>=6, valid=true, timeout=false при budget18s;
это симуляция текстового этапа условной минуты, не запуск ASR на минутном аудио.
