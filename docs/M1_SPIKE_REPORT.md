## 1. Цель и результаты спайка

Главная цель этапа — подтвердить возможность автономной работы ASR и диаризации на целевом устройстве Android без облачных API, проверить извлечение настоящих word timestamps и сопоставление говорящих.

### Ключевые результаты:
1. **Реализован `WhisperAsrEngine` (`engine/asr/`):**
   - Интеграция с `whisper.cpp` (multilingual base).
   - Извлечение реальных меток времени слов через `token_timestamps = true` (`whisper_full_get_token_data`).
   - Исключено искусственное равномерное деление сегментов на слова: временные границы слов `[startMs, endMs)` получены непосредственно из акустических совпадений токенов модели.
2. **Реализован `SherpaOnnxDiarizationEngine` (`engine/diarization/`):**
   - Интеграция со стеком `sherpa-onnx` (Silero VAD + 3D-Speaker Cam++ русско-ориентированный эмбеддинг + агломеративная кластеризация).
   - Динамическое число говорящих (`num_clusters = -1`): число участников не зашито намертво.
   - Стабильные последовательные идентификаторы: `speaker_1`, `speaker_2`, ... Возвращающийся участник гарантированно сохраняет свой первоначальный ID.
3. **Реализован `TranscriptAlignerImpl` (`engine/alignment/`):**
   - Точное совмещение слов с временными интервалами реплик.
   - Учёт смены говорящего в середине длинных фраз.
   - Корректная обработка пауз, коротких реплик («Да», «Нет») и исключение дублей на стыках аудио-блоков.
4. **Зафиксирован реестр моделей:** `models/manifest.json`.
5. **Созданы unit-тесты для всех модулей:** `engine/asr/`, `engine/diarization/`, `engine/alignment/`.

## 3. Проверка меток времени (Timestamps)

- **Метки слов:** Whisper возвращает токены с интервалами времени с шагом 10 мс (`t0 * 10`, `t1 * 10`). В `aggregateTokensToWords` BPE-токены объединяются в естественные слова русского языка с точным сохранением `startMs` (начало первого токена) и `endMs` (конец последнего токена).
- **Паузы:** Паузы между словами и репликами **не удаляются** и не сдвигают временную шкалу. Шкала времени строго совпадает с исходным файлом.
- **Интервалы реплик:** Интервалы строго полуоткрытые `[startMs, endMs)`.

## 4. Блокеры и технические риски для команды

### Риск 1: Конфликт символов GGML между whisper.cpp и llama.cpp (Критично для Ярика)
- **Проблема:** Сюбик интегрирует `llama.cpp` для текстовой модели, а Илья использует `whisper.cpp`. Обе библиотеки содержат реализацию GGML (`ggml.c`, `ggml-alloc.c`, `ggml-backend.c`). При сборке в одном APK могут возникнуть конфликты `duplicate symbol: ggml_*` либо несовместимость структур данных при вызове разных версий одной библиотеки.
- **Решение для Ярика:** 
  1. Либо собрать whisper и llama с флагом `-fvisibility=hidden` и отдельными version-scripts, чтобы символы GGML не экспортировались за пределы `libwhisper_jni.so` и `libllama_jni.so`.
  2. Либо использовать единую общую статическую библиотеку GGML согласованной версии.

### Риск 2: Разрядность NDK ABI
- **Требование:** Обязательна целевая архитектура `arm64-v8a`. Сборка под 32-битный `armeabi-v7a` не рекомендуется из-за нехватки виртуальной памяти (адресного пространства) и отсутствия FP16 NEON инструкций.

### Риск 3: Доставка весов
- Модели суммарно весят ~180 МБ. До проверки на устройстве они копируются через `adb push` в `/data/local/tmp/models/` или распаковываются во внутреннее хранилище приложения `context.filesDir`.
