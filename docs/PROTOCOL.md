Результаты чужого тестирования имеют статус reported, не agent-measured. Проверка экспорта JFK PASS сообщена Яриком; этот PR не повторяет её без выгруженного JSON.

## Идентификация нового прогона

До старта записать в локальный журнал: дату/время и timezone, тестировщика, git SHA сборки, APK SHA-256, build variant/realEngines и native optimization; модель устройства/Android/ABI/RAM, заряд/температуру (если доступны), состояние сети; условный ID входа, язык, длительность PCM/аудио и хеш разрешённого входа локально. Хеш APK и вариант обязательны для переноса результата на конкретную сборку.

Для финальной поставки проверить именно release через UI; instrumentation/debug и standalone LLM — самостоятельные сценарии. Включить авиарежим, отдельно убедиться, что Wi-Fi выключен. Отсутствие INTERNET в manifest проверить для конкретного APK, не по другому артефакту.

## Чистая установка, cold и warm

1. Чистая установка: на тестовом устройстве установить APK без ранее скопированных моделей/данных приложения; зафиксировать, как это обеспечено. `adb install -r` сам по себе **не** доказывает чистую установку.
2. Cold после чистой установки: измерить полный путь до результата и отдельно копирование assets→filesDir, checksum/native load и собственно обработку. Если отдельные часы недоступны — оставить поле пустым, описать границу общего таймера.
3. Cold процесса: повтор после остановки процесса при уже скопированных весах — отдельный режим, не смешивать с cold_clean. Файловый cache ОС не считать очищенным без подтверждения.
4. Warm: повторить тот же вход на той же сборке без остановки процесса; минимум 3 повтора для нового протокола, все результаты сохранить. Для KV runtime важен его lifetime: закрытие модели между pipeline jobs не сохраняет кэш между ними. При scalar↔batch меняется префикс.
5. Зафиксировать крэш/ошибку/отмену и warning, не заменять неуспех нулевым временем.

Старые cold/warm измерения не объявляются выполненными по всем этим новым правилам.

## Метрики

- Длительность исходного аудио и wall time: отдельно decode, diarization, ASR, alignment, prepare/load, LLM generation/validation, export и end-to-end. Не складывать пересекающиеся интервалы. RTF = processing_seconds / audio_seconds; указать, входит ли копирование. При неизвестной длительности RTF не вычислять.
- RAM: peak PSS и RSS раздельно, с единицами/методом и частотой sampling; одиночный dumpsys не является доказанным пиком. Ранее сообщённый пик пометить reported, метод неизвестен.
- LLM: M всего реплик; N завершённых, accepted/changed/rejected отдельно; warning и необработанный остаток. N из warning не приравнивать к числу изменённых строк. Зафиксировать nominal 30% и фактическое превышение первой порцией #24.
- Качество: WER/CER/DER только с разрешённым эталоном и документированной нормализацией. Лексический guard не заменяет сравнение ASR с эталоном.
- Экспорт: schema/invariants через существующий quality/check_export.py; сохранить verdict/числа. Не публиковать текст JSON реального кейса.
